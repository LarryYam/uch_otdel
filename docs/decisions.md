# Журнал решений

Короткие записи: что решили, почему и чем пожертвовали. Новое решение — новая запись внизу;
отменённое не удаляем, а помечаем «Заменено записью N».

## 1. Веб-приложение на Blazor Server

**Решение.** Веб, а не десктоп; Blazor Server.
**Почему.** Нагрузку согласуют много ролей одновременно; нет установки на каждый ПК; одна база кода;
логику на C# можно перенести из старой программы. Server, а не WebAssembly: данные и правила остаются на сервере,
быстрый старт, проще безопасность.
**Цена.** Нужен сервер; нет офлайна; на каждую открытую вкладку тратится память сервера.

## 2. Компоненты Radzen.Blazor (MIT)

**Решение.** Radzen, только бесплатные компоненты. DevExpress и другие платные наборы не используем.
**Почему.** Бесплатно для коммерческого продукта; грид с фильтрами, группировкой, редактированием, сводная таблица.
Проверено прототипом.
**Цена.** Нет готового выделения произвольных ячеек и копирования блоков в Excel — делаем своей обёрткой над гридом.

## 3. EF Core, две СУБД: SQL Server и PostgreSQL

**Решение.** EF Core; поддерживаем SQL Server и PostgreSQL с первого дня; миграции — отдельный проект на СУБД.
**Почему.** Крупные вузы со своим SQL Server; колледжи без лицензии — на бесплатном PostgreSQL.
**Цена.** Миграции создаются дважды; запросы проверяются на обеих СУБД (интеграционные тесты в CI).

## 4. Без хранимых процедур, логика в C#

**Решение.** Все правила расчёта — в Domain, запросы — LINQ.
**Почему.** Независимость от СУБД; правила проверяются юнит-тестами; их можно сверить со старой программой.
**Цена.** Формулы из процедур старой программы нужно переносить вручную.

## 5. Контекст данных на одну операцию

**Решение.** `IAppDbContextFactory`, контекст создаётся в каждом методе сервиса.
**Почему.** Особенность Blazor Server: долгоживущий контекст копит объекты и не допускает параллельных операций.

## 6. .NET 10

**Решение.** .NET 10 (LTS), Visual Studio 2026.
**Почему.** Поддержка .NET 8 и 9 заканчивается в ноябре 2026.

## 7. Часы экзамена хранятся, а не вычисляются при чтении

**Решение.** `Assignment.ExamHours` сохраняется в базе и пересчитывается при изменении студентов или признака экзамена.
**Почему.** Изменение норм не должно задним числом менять уже утверждённую нагрузку.
**Цена.** При смене норм нужна явная операция «пересчитать по новым нормам» (будет добавлена).

## 8. Дисциплина пока строкой

**Решение.** `Assignment.Discipline` — строка, справочника дисциплин пока нет.
**Почему.** Так устроен прототип; справочник появится вместе с учебными планами (РУП).

## Открытые вопросы

- Учебный год: хранить несколько лет в одной базе, копирование нагрузки из прошлого года.
- Мультиарендность для облака: отдельная база на вуз или общая база с `OrganizationId`.
- Пользователи и права: собственная авторизация или вход через систему вуза (AD, Keycloak и т.п.).
- Нормы в базе по организации и году вместо `appsettings.json`.
- Имена таблиц в PostgreSQL: сейчас PascalCase в кавычках; при необходимости — snake_case для PostgreSQL.
