# Предметная область

> Документ — основа для разработки и для работы с Claude. Составлен по итогам интервью с автором
> старой программы (ноябрь 2026). Правила здесь — решения заказчика; всё, что не решено, вынесено
> в раздел «Открытые вопросы». Список функций по приоритетам — `docs/requirements.md`.

## Назначение

Система помогает учебно-методическому отделу, деканатам и кафедрам рассчитать и распределить учебную
нагрузку на учебный год: какие виды работ, у каких групп, подгрупп и потоков и в каком объёме выполняет
каждый преподаватель по каждому договору, — и проконтролировать, что нагрузка соответствует ставке.

**Клиенты.** Около 150 организаций старой программы «АС Нагрузка ВУЗа»: вузы и СПО России, а также
вузы в Бишкеке (КРСУ), Ереване и Минске. От крупных вузов (СФУ, МГИМО Одинцово, МПГУ, СПбПУ) со своим
ИТ-отделом до организаций, где с системой работает один человек.
Следствие: нормы, справочники и правила не зашиваются под нормативы одной страны — всё настраивается.

## Годовой цикл

Последовательность действий пользователя сохраняется такой же, как в старой программе.

1. **Весна.** Загружаются все учебные планы (.plx). Группы создаются автоматически.
2. Методист уточняет контингент групп (в т. ч. по источникам финансирования) и настройки расчёта
   (правила деления на подгруппы и формирования потоков).
3. **Расчёт нагрузки.** Во время расчёта создаются подгруппы, после расчёта собираются потоки.
4. Расчёт штата — общего числа ставок по кафедрам (несколькими методами). *Не в первой версии.*
5. Заведующие кафедрами формируют ППС (договоры) и распределяют нагрузку между преподавателями.
6. Преподаватели получают нагрузку и дополняют индивидуальный план второй половиной дня. *Не в первой версии.*
7. **Осень.** После набора контингент уточняется → перерасчёт нагрузки → заведующие корректируют
   распределение, преподаватели — индивидуальные планы.
8. Заполняется факт выполнения. *Не в первой версии.*

Первая версия выпускается по разделам: **Планы и группы → Правила расчёта → Нагрузка**.

## Организация и структурные подразделения

- **Одна база данных — одна организация** (стандартный вариант).
- **Структурные подразделения** — иерархический справочник (таблица с рекурсией), например
  факультет → кафедра. Реальная структура сложнее; у каждого элемента есть пометки (тип и т. п.),
  по которым работают правила и права.
- **Филиалы и подразделения СПО** вуза — это узлы того же дерева, а не отдельные организации.
- К кафедрам привязаны **образовательные программы**, программы состоят из **дисциплин**.
- Эта цепочка (подразделения → программа → дисциплина) — **дерево детализации**, к которому
  привязываются нормы, правила деления на подгруппы и правила формирования потоков.

## Учебные планы

- Планы загружаются из файлов **.plx**; файл читается полностью. Других форматов пока нет.
- Каждая строка плана имеет **id** из файла. Каждое поручение хранит ссылку на строку плана,
  из которой оно возникло.
- **Перезагрузка плана** (бывает несколько раз за год):
  - строки сопоставляются только по id; новый id — это удаление старой строки и добавление новой
    (переименование дисциплины с новым id — тоже замена);
  - значения из файла имеют приоритет над ручными правками плана в программе;
  - если строка плана изменилась или удалена, связанные поручения **не меняются автоматически**,
    а получают пометку «план изменился»; решение принимает методист.
- Методист может вносить **точечные правки** плана в программе (например, сменить кафедру,
  за которой закреплена дисциплина).
- **Виды работ** — динамический справочник: приходит с планом, методист может менять его в конкретном плане.
  Вид работ определяется по id.
- **Справочник дисциплин** формируется из планов. Одинаковые дисциплины разных планов объединяются
  автоматически по названию; совпадение зачётных единиц — дополнительный признак (включается настройкой).

## Группы и контингент

- Группы создаются автоматически при загрузке плана по данным плана (курсы, число групп и студентов в .plx).
- Атрибуты группы: название, курс, форма обучения, структурное подразделение, планы, контингент.
- **Контингент** вводится по источникам финансирования. **Источники финансирования** — редактируемый
  справочник организации; по умолчанию «бюджет / внебюджет», может детализироваться
  (бюджет федеральный, региональный, местный; договор; целевое и т. п.).
  На расчёт нагрузки источник не влияет; разбивка нужна бухгалтерии: нагрузка строки распределяется по
  источникам **пропорционально числу студентов**. Ввод вручную; интеграция — позже.
- **Связь «план — группа»**: студенты одной группы могут учиться по разным планам.
  Практический случай — **индивидуальный план** студентов, у которых часть дисциплин перезачтена:
  - перезачтённая дисциплина не меняет аудиторные часы группы, а расчётные часы (например, экзамен)
    считаются без этих студентов;
  - если в индивидуальном плане есть дисциплина, которой нет у группы, под неё создаётся отдельное
    поручение на этих студентов.

## Правила расчёта

### Состав нагрузки

Нагрузка по строке делится на две части:

- **аудиторная (Ауд)** — приходит из плана;
- **другая (Др)** — рассчитывается по нормам.

Нагрузка детализируется максимально: каждый вид работ — отдельная строка, которую можно отдать
отдельному преподавателю. Производные виды работ (например, консультации в размере 15 % от часов плана
по виду занятий) — тоже отдельные строки.

### Нормы

- Нормы задаются **таблицей**, близкой по виду к положению о нормировании времени
  (в старой программе — неструктурированное окно, это нужно исправить).
- Норма зависит от вида работ и может зависеть от: часов плана, числа студентов, числа работ, числа недель
  (практики) и т. п.; от организации, уровня образования, формы обучения, учебного года; от численности
  (малочисленные группы); от дисциплины и вида занятий.
- Число групп и подгрупп **в формулу нормы не входит** — оно определяет число строк нагрузки и через них
  итоговую сумму.
- Примеры норм:
  - коэффициент для малочисленных групп: таблица «[число студентов, значение]»;
  - дисциплины на иностранном языке — вдвое больше времени;
  - консультации — 15 % от часов плана по виду занятий;
  - ограничение: председателю ГЭК 1 ч на студента, но не более 8 ч в день.
- **Выбор нормы.** Программа перебирает все нормы и проверяет, подходит ли каждая к строке.
  Срабатывают **все** подходящие нормы. Если одна и та же норма задана на разных уровнях дерева
  детализации, применяется **самая детализированная**.
- **Одинаковые нормы** — нормы на один и тот же вид работ с одинаковыми условиями (уровень, форма,
  численность и т. п.), различающиеся только уровнем дерева.
- **Порядок детализации** (от общего к частному): общая → структурные подразделения (по глубине дерева)
  → образовательная программа → дисциплина. Норма программы детальнее нормы кафедры.
- **Нормы не нашлось** — берётся значение из плана.
- Для работ, не связанных со строками плана, предусматриваются отдельные виды норм.
- Нормы ведёт специалист учебно-методического отдела (обычно начальник или его помощник).
- Нормы — справочник организации, он переходит из года в год (условие по году — часть нормы).

### Ограничения «не более N»

Ограничение относится к нагрузке, которую можно выделить преподавателю, и действует на день.
Число дней вводит методист в поручении. Пример: 1 ч на студента, не более 8 ч в день, 3 дня защит:
20 студентов → 20 ч; 28 студентов → min(28; 3 × 8) = 24 ч.

### Коэффициент

- Отдельная колонка в гриде нагрузки. Заполняется вручную или специальными командами (разработаем позже).
- Если к строке подходят несколько коэффициентов, в колонку записывается их **произведение**
  (например, малочисленная группа 0,8 × иностранный язык 2 = 1,6).
- Два способа применения, выбирается в настройках **по учебному году**:
  1. Итог = Ауд + Др × Коэф;
  2. Итог = (Ауд + Др) × Коэф.

### Подгруппы

- Создаются при расчёте; в .plx подгрупп нет.
- Правила деления настраиваются до расчёта в интерфейсе «Настройки расчёта» и привязываются к дереву
  детализации; применяется самое детальное правило. Примеры:
  - общее: лабораторные — не более 18 студентов в подгруппе;
  - кафедра физической культуры: не более 10 студентов;
  - кафедра иностранных языков: фиксированный состав независимо от численности —
    две подгруппы английского и одна немецкого (численность задаёт методист);
  - дисциплина: Информатика, практические — не более 12 (12 компьютеров); Химия, лабораторные — не более 8.
- Контингент по умолчанию делится равномерно; методист может корректировать.
- Подгруппы из студентов разных групп: сначала подгруппы создаются в каждой группе, затем объединяются в поток.
- Ручные правки подгрупп **сохраняются** при перерасчёте.
- Студентов стало больше и нужна новая подгруппа — она создаётся нераспределённой, закреплённый
  преподаватель остаётся на исходной подгруппе; новую подгруппу распределяет заведующий.
- Студентов стало меньше — лишняя подгруппа удаляется (в т. ч. с ручными правками); удаление пишется
  в журнал с возможностью отката.

### Потоки

- Правила формирования потоков настраиваются до расчёта в «Настройках расчёта» по дереву детализации
  и видам занятий: максимальное число студентов в потоке.
- Потоки собираются автоматически. Минимальные условия объединения: совпадают дисциплина, вид занятий,
  форма обучения, часы, семестр и кафедра. Детальные правила — при разработке.
- При превышении максимума программа сначала группирует по направлению подготовки
  (например, 4 + 2, если 4 группы одного направления и 2 другого), иначе делит равномерно.
- Вручную в поток можно объединить что угодно (любые виды занятий, подгруппы, группы разных кафедр,
  форм и планов). Превышение максимума — предупреждение, не запрет.
- **Аудиторные часы** потока считаются один раз — у первой группы; первую группу методист может переназначить.
  **Расчётные часы** (экзамен, консультации и т. п.) считаются для каждой группы.
- Нормы, зависящие от численности потока, не нужны.
- Изменение плана у группы в потоке поток не меняет; событие пишется в журнал.

### Перерасчёт

- Выполняется сразу, без предварительного просмотра; все изменения пишутся в журнал с возможностью отката.
- Сохраняются: закреплённые преподаватели, потоки, ручные правки подгрупп.
- Сохранённые часы не меняются задним числом при изменении норм — пересчёт по новым нормам запускается явно.

## Преподаватели, договоры, ставки

- Загрузка учитывается **по каждому договору** человека с организацией. У одного человека может быть
  несколько договоров (например, штатный на кафедре А и внутренний совместитель на кафедре Б).
- **Виды занятости:** штатный, внутренний совместитель, внешний совместитель, почасовик, договор ГПХ.
- **Норма по договору** = ставка × норма часов на ставку.
  Норма часов на ставку зависит от **должности** и **учебного года**; ориентир: ВО — не более 900 ч,
  СПО — 720 ч.
- **Договор на часть года:** норма пересчитывается по отработанным месяцам (в году 10 месяцев,
  2 — отпуск): норма × отработанные месяцы / 10.
- **Почасовик:** ставки нет; не более 300 ч на человека в учебный год.
- **ГПХ:** только разовые виды работ (например, участие в комиссии); регулярную работу (вести дисциплину)
  по ГПХ поручать нельзя. Отдельного признака у вида работ не делаем.
- **Ограничения:** не более 1,5 ставки на человека в организации (сумма по договорам); почасовка — не более
  300 ч на человека в год. Нарушение — **предупреждение** (подсветка красным), сохранение не запрещается.
- **Неучебная нагрузка** (вторая половина дня) положена штатным и обоим видам совместителей;
  почасовикам и по ГПХ — нет. *Не в первой версии.*
- Процент загрузки показывается как сопутствующая информация.
- Список договоров по умолчанию заводит заведующий кафедрой, ориентируясь на прошлый год;
  интеграция с кадрами — позже.

## Учебный год и журнал

- Все учебные годы хранятся в одной базе; пользователь переключается между ними.
- Работать в нескольких годах может администратор; остальным это разрешается настройкой.
  Менять можно всё, в любом году.
- Новый год начинается с чистого листа; справочники (структурные подразделения, нормы) остаются.
  Перенос планов, групп, преподавателей, распределения из прошлого года (со сдвигом курса) — отдельными
  командами, *не в первой версии*.
- **Журнал изменений** — полный (кто, когда, что было, что стало), хранится бессрочно; показывается журнал
  выбранного учебного года; возможна ручная чистка.
- **Откат** — к дате и времени, с комментарием; можно выбрать область: план, кафедра, подразделение,
  отдельная строка нагрузки.

## Пользователи и права

- Права выдаются на **функции** (функция = интерфейс, например «Планы и группы») и **действия** в них
  (просмотр, редактирование), с **областью**: подразделения дерева или образовательные программы.
- Область распространяется вниз по дереву: декан факультета видит все его кафедры.
- **Роль** — шаблон функций по умолчанию; набор функций конкретного пользователя можно менять.
  У пользователя может быть несколько ролей.
- Откат — тоже функция (по умолчанию у супер-админа, может быть выдана любому).

| Роль | Функции по умолчанию | Область |
|---|---|---|
| Супер-админ (ИТ) | Всё, включая обновления, интеграции, пользователей, роли | Вся организация |
| Учебный отдел | Планы, группы, нагрузка: расчёт и корректировка | Вся организация или выбранные подразделения |
| Декан | Просмотр нагрузки, корректировка контингента | Свой факультет |
| Заведующий кафедрой | ППС (договоры), распределение нагрузки | Своя кафедра |
| Руководитель ООП | Просмотр и корректировка | Свои образовательные программы |
| Преподаватель | Заполнение индивидуального плана | Свои договоры |
| Диспетчер расписания | Просмотр нагрузки | По назначению |

- В небольшом колледже с одним методистом достаточно одного пользователя с ролью «Учебный отдел» на всю организацию.
- Вход в первой версии — как в старой программе: логины и пароли хранятся в базе приложения.
- Статусы нагрузки (черновик → … → утверждено) будут; уровень, на котором ставится статус, определим позже.
- Изменение утверждённой нагрузки не запрещается: показывается предупреждение, изменение пишется в журнал.

## Глоссарий

«—» в колонке «В коде» — сущности ещё нет.

| Термин | Значение | В коде |
|---|---|---|
| Организация | Вуз или колледж; одна организация — одна база данных | — |
| Структурное подразделение | Узел иерархического справочника: факультет, кафедра, филиал, подразделение СПО и т. п. | — (сейчас `Department`) |
| Кафедра | Подразделение, за которым закреплены дисциплины и договоры преподавателей | `Department` |
| Образовательная программа (ООП) | Программа, привязанная к кафедре; состоит из дисциплин | — |
| Дерево детализации | Подразделения → программа → дисциплина; к нему привязываются нормы и правила | — |
| Учебный план | План из файла .plx | `StudyPlan` |
| Строка плана | Дисциплина/вид работ плана с id из файла; источник поручений | — |
| Вид работ | Элемент динамического справочника плана (лекции, практические, экзамен, курсовая, ГЭК…) | — (сейчас поля `Assignment`) |
| Дисциплина | Элемент справочника дисциплин, общего для планов | — (сейчас строка `Assignment.Discipline`) |

## Что реализовано в прототипе

Правила ниже работают сейчас и будут заменены нормами из базы по описанным выше правилам.

1. **Норма преподавателя** = ставка × `HoursPerRate` (по умолчанию 600 ч).
2. **Часы экзамена** = `ConsultationHoursPerGroup` (2 ч) + `ExamHoursPerStudent` (0,33 ч) × число студентов,
   округление до 0,1 ч от нуля. Нет экзамена или студентов — 0.
3. **Итог поручения** = лекции + практические + лабораторные + экзамен.
4. **Статус**: больше 100 % нормы — перегруз; меньше `UnderloadThresholdPercent` (90 %) — недогруз; иначе норма.
5. Выбор группы в поручении подставляет её численность; число студентов можно уменьшить (подгруппа).
6. Новая связь «план — группа» по умолчанию забирает всех ещё не распределённых студентов группы, минимум одного.

Нормы прототипа задаются в `appsettings.json`, секция `Norms`.
